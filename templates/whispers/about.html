{% trans "About psst-secret" %}

{% trans "A privacy focused app for sharing secrets securely. We call them whispers." %}

{% trans "How It Works" %}

{% trans 'psst-secret ensures that your whispers never exist in plaintext on our server. All encryption and decryption happens entirely in your browser using the Web Crypto API.' %}

📤 {% trans "Send Mode" %}

{% trans "Share a whisper with someone. The key travels only inside the link you share." %}

🔒 {% trans "Creating a Whisper" %}

  1. {% trans "You type your whisper in the browser" %}
  2. {% trans 'A random AES-256-GCM key is generated client-side' %}
  3. {% trans "Your whisper is encrypted in-browser" %}
  4. {% trans "Only the ciphertext is sent to the server" %}
  5. {% trans 'The decryption key is placed in the URL fragment (#key)' %}

🔓 {% trans "Viewing a Whisper" %}

  1. {% trans "You open the shared link" %}
  2. {% trans "The server returns the ciphertext" %}
  3. {% trans "The key from the URL fragment decrypts it in-browser" %}
  4. {% trans "You see the plaintext — the server never does" %}

⚛️ {% trans "Send mode uses only symmetric encryption (AES-256-GCM), which is not broken by quantum computers. The known quantum attack on symmetric ciphers (Grover's algorithm) at most halves the effective key strength, leaving 128 bits — still far beyond reach. Shor's algorithm, the real quantum threat, only affects public-key cryptography, which send mode does not use." %}

📥 {% trans "Receive Mode" %}

{% trans 'Ask someone to send a whisper to you. Receive mode uses public-key encryption, so the person submitting can encrypt but never decrypt.' %}

🔑 {% trans "Creating a Request" %}

  1. {% trans 'Your browser generates a key pair using X-Wing, a hybrid of ML-KEM-768 (post-quantum, FIPS 203) and X25519' %}
  2. {% trans "The public key is stored on the server. The submit link contains only its fingerprint, so the server cannot swap in a key of its own" %}
  3. {% trans "The private key seed stays in your view link fragment (or is encrypted with your password)" %}
  4. {% trans "You share the submit link and keep the view link" %}

🔓 {% trans "Submitting & Viewing" %}

  1. {% trans "The sender opens the submit link and types their whisper" %}
  2. {% trans "The sender's browser encrypts to your public key and uploads only the ciphertext" %}
  3. {% trans "You open your view link" %}
  4. {% trans "Only your view link can decrypt it" %}

{% trans "The submit link and view link use different identifiers. Someone who gets hold of the submit link cannot find, read, or burn the submitted whisper." %}

⚛️ {% trans "Because the key exchange is hybrid, the whisper stays protected as long as either algorithm holds — including against attackers who record traffic today and hope to decrypt it with a quantum computer later." %}

{% trans "Why the URL Fragment?" %}

{% trans "The decryption key is stored after the # in the URL, known as the fragment. The URI specification (RFC 3986 §3.5) reserves the fragment for processing by the browser, and the HTTP specification (RFC 9110 §7.1) excludes it from the request — so the URL fragment is never sent to the server. This means:" %}

  • {% trans "The server never receives the decryption key" %}
  • {% trans "The key doesn't appear in server logs or analytics" %}
  • {% trans "Even if the server is compromised, your whispers remain encrypted" %}

🔑 {% trans "Password Protection" %}

{% trans "Optionally, you can set a password when creating a whisper. When a password is used:" %}

  • {% trans 'The encryption key is derived from your password using PBKDF2 (600,000 iterations, SHA-256)' %}
  • {% trans 'A random salt is generated and stored on the server (useless without the password)' %}
  • {% trans "The URL contains no key fragment — only the password holder can decrypt" %}
  • {% trans "For receive requests, the password protects your private key instead. The sender does not need it — only you do, to open the view link" %}
  • {% trans "This provides an extra layer of security for highly sensitive data" %}
